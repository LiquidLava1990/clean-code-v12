# Clean Code V12 — VS Code extension

Squiggles, hovers, and quick-fixes powered by the
[Clean Code V12](https://github.com/LiquidLava1990/clean-code-v12) linter. The
extension is a thin wrapper over the `cc-lsp` daemon: every diagnostic
you see in the editor is the same finding `ccv12 check` would emit on the
command line.

## Features

- Inline diagnostics (`blocker` / `required` / `nit`) for Python,
  TypeScript, JavaScript, Rust, and Go.
- Hover docs on every finding, sourced from the rule's stable id.
- Code actions for autofixable rules (where the rule provides a patch).
- Workspace-aware: respects `.cc/config.toml` and `.cc/baseline.json`
  exactly like the CLI.
- One command: **Clean Code V12: Restart Server**.

## Requirements

You need the Clean Code V12 server binary on your machine. There are two
supported deployment shapes:

1. **Standalone daemon (current default).** Build or download the
   `cc-lsp` binary and put it on `PATH`, or point
   `cleanCodeV12.server.path` at it directly.
   ```sh
   cargo install --path crates/cc-lsp     # from a v12 checkout
   # or
   cargo build --release -p cc-lsp        # then copy target/release/cc-lsp
   ```
2. **Unified CLI (future).** Once the `ccv12` CLI grows an `lsp`
   subcommand, set `cleanCodeV12.cli.path` to a workspace-customised
   value and the extension will spawn `ccv12 lsp --stdio` instead. As of
   v0.1.0 the CLI does **not** ship this subcommand (verified against
   `crates/cc-cli/src/args.rs`); the standalone daemon path is the
   active default.

## Settings

| Setting | Default | Description |
| --- | --- | --- |
| `cleanCodeV12.cli.path` | `ccv12` | Path to the `ccv12` CLI. Used only when customised in workspace/user settings — see *Requirements* above. |
| `cleanCodeV12.server.path` | `cc-lsp` | Path to the standalone `cc-lsp` daemon binary. |
| `cleanCodeV12.severity` | `required` | Minimum severity surfaced as a diagnostic (`blocker`, `required`, or `nit`). |
| `cleanCodeV12.trace.server` | `off` | LSP trace verbosity (`off`, `messages`, `verbose`). |

## Commands

| Command | id |
| --- | --- |
| Clean Code V12: Restart Server | `cleanCodeV12.restart` |

## Build from source

```sh
cd editors/vscode
npm install
npm run compile          # produces out/extension.js
npm run package          # produces clean-code-v12-0.1.0.vsix
code --install-extension clean-code-v12-0.1.0.vsix
```

The repository deliberately does not ship `node_modules/` or the
compiled `out/` directory; both are regenerated by `npm install` +
`npm run compile`.
